Pre-required installed tools on mgmt machine:

  • talosctl
  • kubectl
  • helm
  • flux

Talos deploy schema: ￼

  • [PX-0] 1 x beeline gti13 ultra i9-1300hk 64gb ram -> 1 worker + 1 controlplane
  • [PX-1] 1 x dell optiplex 3050 i5-6500T 32g ram -> 1worker + 1 controlplane
  • [PX-2] 1 x dell optiplex 3050 i5-6500T 32g ram -> 1worker + 1 controlplane

Generate secrets
#

  talosctl gen secrets

longhorn-mount.yaml is required only if you want to deploy longhorn in your cluster
#

talosctl gen config meroxdev-k8s-cluster --kubernetes-version=1.32.5 https://10.57.57.80:6443 \
  --with-secrets secrets.yaml \
  --config-patch @cni.yaml \
  --config-patch @kubeprism.yaml \
  --config-patch @interface-persistent-name.yaml \
  --config-patch @kubelet-certificate.yaml \
  --config-patch @longhorn-mount.yaml \
  --config-patch-control-plane @vip.yaml \
  --output rendered/
  • cni - used for don’t pre-install an CNI on the cluster
  • kubeprism - enabled needed for Cilium deployment later (https://www.talos.dev/v1.10/kubernetes-guides/network/deploying-cilium/)
  • interface-persistent-name - to be sure kernel will not change it later after some upgrade reboot ( check this information if it’s true )
  • kubelet-certificate - To renew the certificate when it’s expired
  • longhorn-mount - needed as explained here: https://longhorn.io/docs/1.9.0/advanced-resources/os-distro-specific/talos-linux-support/ #data-path-mounts
  • vip - for virtual IP on controlplanes

all files are located in talos/patches

Deploy controlplanes:
#

  talosctl apply -f rendered/controlplane.yaml -n 10.57.57.80 --insecure
  talosctl apply -f rendered/controlplane.yaml -n 10.57.57.82 --insecure
  talosctl apply -f rendered/controlplane.yaml -n 10.57.57.84 --insecure

Deploy workers:
#

  talosctl apply -f rendered/worker.yaml -n 10.57.57.81 --insecure
  talosctl apply -f rendered/worker.yaml -n 10.57.57.83 --insecure
  talosctl apply -f rendered/worker.yaml -n 10.57.57.85 --insecure

Copy talosctl config
#

  cp rendered/talosconfig ~/.talos/config

Set endpoints & node
#

  talosctl config endpoint 10.57.57.80 10.57.57.82 10.57.57.84
  talosctl config node 10.57.57.80

Deploy k8s cluster
#

  talosctl bootstrap -n 10.57.57.80

Get kubectl config local
#

  talosctl kubeconfig -n 10.57.57.88

Make kubeconfig default in your shell
#

cp kubeconfig ~/.kube/config

My flux workflow contain configuration for longhorn and I will need to use a specific Talos image with 2 specific extensions So I will go to https://factory.talos.dev/ to upgrade the VMs based on longhorn docs(https://longhorn.io/docs/1.9.0/advanced-resources/os-distro-specific/talos-linux-support/)

I made a script to update the talos with needed extensions

#Schematic ID will be generated after you chose your extensions on factory.talos.dev, this one is for longhorn compatibility
SCHEMATIC_ID=613e1592b2da41ae5e265e8789429f22e121aab91cb4deb6bc3c0b6262961245
# Talos version
VERSION=v1.10.3
IMAGE="factory.talos.dev/metal-installer/$SCHEMATIC_ID:$VERSION"
# Change with talos machines where you want to deploy longhorn instances
for ip in 10.57.57.81 10.57.57.83 10.57.57.85; do
  talosctl -n $ip upgrade --image $IMAGE --preserve
done

I use SOPS+Age to encrypt my secrets from Flux deployment, so one last step before provisioning the infrastructure+apps on the cluster is

# Creează namespace-ul flux-system dacă nu există
kubectl create namespace flux-system --dry-run=client -o yaml | kubectl apply -f -

# Create secret with AGE key inn cluster
kubectl create secret generic sops-age \
  --namespace=flux-system \
  --from-file=age.agekey=age-key.txt

label nodes for longhorn
#

kubectl label nodes kubernetes-worker-1 kubernetes-worker-2 kubernetes-worker-3 computestorage=true

Bootstrap flux on cluster
#

flux bootstrap github \
  --components-extra=image-reflector-controller,image-automation-controller \
  --owner=meroxdotdev \
  --repository=flux \
  --branch=main \
  --path=clusters/merox \
  --personal \
  --token-auth
